# Dialect `flutter`: the `mobile` platform in Dart

> The Dart dialect of the [mobile platform](mobile.md) (ADR-0093). Inherits every rule of
> [nuclear-base.md](https://github.com/nuclearlang/nuclear/blob/main/spec/nuclear-base.md) and of the [dart](https://github.com/nuclearlang/nuclear/blob/main/spec/dart.md) dialect. It generates Flutter apps with a light
> clean architecture (Dragonfly): in Nuclear you write the business logic and the transpiler writes the rest. The code it generates uses the Dart package **`dragonfly`**
> ([dragonfly.md](dragonfly.md), `packages/dragonfly`) for what does not exist in Flutter. Files:
> `dialects/mobile/flutter/`. Examples: [widgets_tour.nuc](../examples/examples-flutter-dialect/widgets_tour.nuc)
> (one file) and [clean-flutter-project](../examples/examples-flutter-dialect/clean-flutter-project)
> (a project). Multi-file projects: [projects.md](https://github.com/nuclearlang/nuclear/blob/main/spec/projects.md).

## 1. Rules


Rules 1–4 are the mobile platform's ([mobile.md](mobile.md) §3: golden rule, only the business logic in Nuclear,
light clean architecture, closed components). What Flutter adds:

5. **The `dragonfly` package and official ecosystem libraries:** what does not exist in Flutter (http
   connections with cache and retries, session, events, network, ACL) is in the Dart package `dragonfly`
   ([dragonfly.md](dragonfly.md)); the rest, in `bloc`/`flutter_bloc` (state), `json_serializable` +
   `json_annotation` (JSON), `get_it` (dependency injection), `dio` (http), `go_router` (routes),
   `connectivity_plus` (network), `flutter_secure_storage` (session).
6. **The Flutter CLI underneath:** creating the app, packages, building and running on devices is done by
   `flutter`; the `dragonfly` CLI calls it inside the generated app (§11).

## 2. Libraries and type definitions

### 2.1 Libraries

| Need | Library | Names imported automatically |
|---|---|---|
| Dragonfly runtime | `dragonfly` (`packages/dragonfly`) | `Http`, `WebSocket`, `Repository`, `Events`, `SessionManager`, `NetworkManager`, `Acl`, `Log`, `FormManager`, `DragonflyForm`, `DragonflyDialog`, `Popups`, `Translations`, `inject`... |
| State | `bloc` + `flutter_bloc` | `Cubit`, `Bloc`, `Emitter`, `BlocProvider`, `BlocBuilder`, `BlocListener`, `BlocConsumer`, `BlocSelector`, `MultiBlocProvider`... |
| Dependency injection | `get_it` | `GetIt` |
| Network | `dio` | `Dio`, `BaseOptions`, `Options`, `Response`, `Interceptor`, `DioException`, `CancelToken`, `FormData`... |
| Routes | `go_router` | `GoRouter`, `GoRoute`, `GoRouterState`... |
| JSON | `json_serializable` (generates the code) + `json_annotation` | `JsonSerializable`, `JsonKey`, `JsonEnum`, `JsonValue`... |
| Connectivity and session | `connectivity_plus`, `flutter_secure_storage` | `Connectivity`, `FlutterSecureStorage`... |

Their type definitions (§2.2) are part of the dialect: their names are imported automatically, their classes
can be extended (`Counter: Cubit<int>`) and their inherited members are used without declaring them (`emit`,
`state`). In Dragonfly, `WebSocket` is the connection of the project config (not the one of `dart:io`).

```nuclear
CounterCubit: Cubit<int>
  ()
    super(0)

  increment() void
    emit(state + 1)

Api
  dio: Dio = Dio()

  load(url: string) string
    response = ~dio.get<string>(url)
    response.data ?? ''
```

```dart
import 'package:dio/dio.dart';
import 'package:flutter_bloc/flutter_bloc.dart';

class CounterCubit extends Cubit<int> {
  CounterCubit() : super(0);

  void increment() {
    emit(state + 1);
  }
}

class Api {
  Dio dio = Dio();

  Future<String> load(String url) async {
    final response = await dio.get<String>(url);
    return response.data ?? '';
  }
}
```

### 2.2 Type definitions

Besides `dart@3.13.5` (from [dart](https://github.com/nuclearlang/nuclear/blob/main/spec/dart.md)), `flutter` uses these type definitions packages
([definitions.md](https://github.com/nuclearlang/nuclear/blob/main/spec/definitions.md)):

```toml
defs = [
  "flutter@3.47.7", "dragonfly@0.1.0", "flutter_bloc@9.1.1", "get_it@9.3.0", "dio@5.11.1",
  "go_router@18.1.1", "connectivity_plus@7.3.2", "flutter_secure_storage@11.2.0", "json_annotation@4.12.0",

```

`flutter_bloc` brings `bloc@9.2.1`. The API of any class can be looked up in Nuclear notation:

```sh
nuclear defs show BlocBuilder --dialect flutter
nuclear defs show Repository.send --dialect flutter
nuclear defs search Button --dialect flutter
```

The packages the project adds (`dependencies` of `config.nuc`, §3.1) get their definitions generated by
`dragonfly flutter add` (§11) into the shared cache `~/.cache/nuclearlang/defs/dart/`
(`$XDG_CACHE_HOME/nuclearlang/defs`), with the version the app resolved (`pubspec.lock`). The ones the project
uses are listed in `build/defs.lock` (`hive@2.2.3`, one per line) and are added to the dialect's on every
`build` and `check`. A package the dialect already knows (dio, go_router...) uses the dialect's.

## 3. Structure of a project


A Dragonfly project has **only `.nuc` files** and `assets/` (the translation dictionaries, §6.16, and the
images, like the splash one). Everything generated (the Flutter app, its `pubspec.yaml`, the Dart code,
`android/`, `ios/`...) goes to `build/`. The dialect is `flutter`. The manifest is `config.nuc` (§3.1): the
package name is its `app(name)` or, without it, the project folder's (in snake_case).

```
{project_name}/
  main.nuc                main(): ~startDragonfly() and runApp(...)
  config.nuc              the project's pubspec: app, environment, dependencies, devDependencies (§3.1)
  config/                 project config: kind appConfig
  shared/                 what every component shares:
    widgets/  events/  models/
    components/           global components: kind component
    guards/               access checks: kind guard
    converters/           JSON converters of model fields: kind converter
    screens/              screens of the whole app (access denied, page not found)
  components/
    {component}/
      {component}_component.nuc   facade: kind appcomponent
      config/             the component's configuration: kind config (optional)
      data/               repositories: kind repository
      domain/
        models/           models (without a header word: kind model)
        usecases/         use cases: kind usecase
        aggregates/       kind aggregate (optional)
        services/         kind service
      presentation/
        {screen}/
          {screen}_screen.nuc
          managers/       kind statemanager and kind formmanager
          state_models/   state models (without a header word: kind statemodel)
          forms/          form models (without a header word: kind form)
        widgets/          the component's widgets
  assets/i18n/{locale}/    dictionaries: {component}.json, shared.json (copied to the app)
  assets/splash/           the splash image (@splash; also copied)
  assets/fonts/{Family}/   fonts: {Family}-{Weight}[Italic].ttf (§3.2)
  assets/shaders/          shaders: *.frag (§3.2)
  assets/{anything}/        images, audio, data: bundled as they are (§3.2)
  test/                   tests (without a header word: kind tests)
  integration_test/       integration tests (kind integration)
  build/                  generated: the Flutter app (build/app); not edited
```

Kind by folder (a declaration without a header word): `components/*/domain/models` and `shared/models` →
`model`; `components/*/presentation/*/state_models` and `components/*/presentation/state_models` →
`statemodel`; `components/*/presentation/*/forms` and `components/*/presentation/forms` → `form`; `test` →
`tests`; `integration_test` → `integration`. The code of `lib/` goes to `build/app/lib/` with the same
structure; `test/` and `integration_test/` go to the app's folders of the same name. What is declared in
`test/` is only visible to the files of `test/`.

### 3.1 `config.nuc`

Its first line names the platform the project is written for and the dialect it is built with (ADR-0093,
[projects.md](https://github.com/nuclearlang/nuclear/blob/main/spec/projects.md) §1): `dragonfly(platform = "mobile", dialect = "flutter")`. `plugins(genkit = true,
googleAI = true)` enables the optional parts of Dragonfly (§6.20, [projects.md](https://github.com/nuclearlang/nuclear/blob/main/spec/projects.md) §3.3): the CLI adds
their packages to the app only when they are enabled.

The project's pubspec written in Nuclear. It is not transpiled: `dragonfly` writes the app's `pubspec.yaml`
with it and loads the type definitions of its packages. They are calls with named arguments; each value is a
string, a number or a boolean:

```nuclear
app(
  name = "shop",
  description = "A Dragonfly app.",
  version = "1.0.0+1",
  usesMaterialDesign = true,
)

// optional: Dragonfly already pins the versions it needs
environment(
  sdk = "^3.9.0",
)

dependencies(
  hive = "^2.2.3",
)

devDependencies(
  hive_generator = "^2.0.1",
)
```

| Section | In the app's `pubspec.yaml` |
|---|---|
| `app(name, description, version, usesMaterialDesign)` | `name`, `description`, `version`, `flutter: uses-material-design` |
| `environment(sdk, flutter)` | `environment` |
| `dependencies(package = "version")` | `dependencies` (with `flutter pub add`); each one has its type definitions (§2.2) |
| `devDependencies(package = "version")` | `dev_dependencies` (no definitions: they are not imported in `lib/`) |

- `config.nuc` has no assets section: fonts, shaders, images and audio are taken from `assets/` by
  convention (§3.2).
- An empty section is not written: `dragonfly flutter add` creates `dependencies` or `devDependencies` with
  its first package and `dragonfly flutter remove` deletes it when the last one goes. A new project has only
  `app(...)`.
- Only the project's own packages are written. Dragonfly adds its own: `dragonfly`, `flutter_bloc`, `fpdart`,
  `go_router`, `json_annotation`; `build_runner`, `json_serializable`, `mocktail`, `bloc_test` and
  `integration_test` to generate code and for tests; `flutter_native_splash` with `@splash`. The full list is
  in `build/app/pubspec.yaml`.
- **Only third-party packages the framework does not use.** A package of the dialect (those of `defs`: dio,
  go_router, flutter_bloc, get_it...) or of Dragonfly (`[project.manifest] reserved`: fpdart, build_runner,
  json_serializable, mocktail...) cannot be written in `config.nuc` (`N0303` on its line, in `check`, `build`
  and the editor) nor added with `dragonfly flutter add`, which rejects it before changing anything: it is
  used directly.
- A package deleted from `config.nuc` is removed from the app on the next `build` (dragonfly records in
  `build/app/.dragonfly_deps` the packages that come from `config.nuc`). Its definitions stay in the cache.
- Another section, an unnamed argument or a value that is not a literal is error `N0303`; `check` and the
  editor check it with the rest of the project.
- A project without `config.nuc` gets one on its first `check` or `build`: the project name, the description
  and version of the app's `pubspec.yaml`, and the third-party packages the app already has.
- The editor (LSP) loads the same definitions (`build/defs.lock`): imports, hover, completion and signatures of
  the added packages; one whose definitions are missing from the cache is a warning in `config.nuc` (they are
  generated with `dragonfly build`).

### 3.2 Assets

Assets are configured **by convention**: they are not written in `config.nuc`. `dragonfly build` copies
`assets/` to the app and writes the keys `assets:`, `fonts:` and `shaders:` of its `pubspec.yaml` from the
files it finds. Those three keys are rebuilt on every build: a deleted file leaves the pubspec.

| Folder | In the app's `pubspec.yaml` |
|---|---|
| `assets/fonts/<Family>/` | `fonts:` one family per folder; each `.ttf`/`.otf`/`.ttc` with its weight and style |
| `assets/shaders/*.frag` | `shaders:` |
| any other folder of `assets/` | `assets:` the folder (images, audio, JSON, dictionaries of §6.16) |

The weight and style of a font come from the last word of its name, after `-` or `_` (the Google Fonts
convention): `Thin` 100, `ExtraLight` 200, `Light` 300, `Regular` 400, `Medium` 500, `SemiBold` 600, `Bold`
700, `ExtraBold` 800, `Black` 900; `Italic` or `Oblique` at the end is italic (`Roboto-BoldItalic.ttf` → 700
italic). A word that is not in the list is 400 (a variable font, `Inter[wght].ttf`). The other files of the
folder (`OFL.txt`) are not bundled.

```
assets/fonts/Roboto/Roboto-Regular.ttf
assets/fonts/Roboto/Roboto-BoldItalic.ttf
assets/shaders/wave.frag
assets/images/logo.png
```

```yaml
flutter:
  assets:
    - assets/images/
  fonts:
    - family: "Roboto"
      fonts:
        - asset: assets/fonts/Roboto/Roboto-Regular.ttf
        - asset: assets/fonts/Roboto/Roboto-BoldItalic.ttf
          weight: 700
          style: italic
  shaders:
    - assets/shaders/wave.frag
```

In code the family is the folder's name: `ThemeData(fontFamily = "Roboto")`,
`TextStyle(fontFamily = "Roboto", fontWeight = FontWeight.w700)`.

- Two files of a family with the same weight and style, or a font outside its family's folder, are an error
  of `check` and `build` (before writing anything), with the name it should have.
- The project's assets belong only to the project: Dragonfly adds no assets nor fonts of its own, and the rest
  of the `flutter:` key (`uses-material-design`) is written by `config.nuc`.

### 5.1 `stateless`

```nuclear
stateless Greeting(name: string, onTap?: VoidCallback)
  build(context: BuildContext) Widget
    GestureDetector(onTap = onTap, child = Text('Hola ${name}'))
```

```dart
class Greeting extends StatelessWidget {
  const Greeting({super.key, required this.name, this.onTap});

  final String name;
  final VoidCallback? onTap;

  @override
  Widget build(BuildContext context) {
    return GestureDetector(onTap: onTap, child: Text('Hola $name'));
  }
}
```

- The header's parameters are `final` fields and named parameters of the `const` constructor: required with
  `required`, optional (`name?: T`) or with a default value without it.
- It is constructed with named arguments: `Greeting(name = 'Ana')`.
- `build` is required (error `N0209` if missing) and carries `@override`, like every method named like a
  member of `StatelessWidget`.

### 5.2 `stateful`

```nuclear
stateful Counter(start: int = 0) with SingleTickerProviderStateMixin
  count: int = 0

  initState() void
    super.initState()
    count = start

  build(context: BuildContext) Widget
    TextButton(
      onPressed = ()
        setState()
          count += 1
      child = Text('${count}'),
    )
```

- Generates the `StatefulWidget` with the parameters (as `stateless`) and its `State` class.
- The block's fields and methods go to the `State`. A header parameter used inside the `State` is read as
  `widget.<name>`: `count = start` → `count = widget.start`.
- `with Mixin` applies to the `State`: `class _CounterState extends State<Counter> with SingleTickerProviderStateMixin`.
- The members of `State` (`setState`, `context`, `widget`, `mounted`...) are available without declaring
  them, and a method named like one of them (`build`, `initState`, `dispose`, `didUpdateWidget`...) carries
  `@override`.
- `setState()` + block → `setState(() { ... })`.
- `build` is required.

## 6. Architecture kinds


### 6.1 `appConfig` and `config`

`appConfig` (in `config/`) declares the app's connections and global services; `config` (in
`components/<c>/config/`) adds those of a component. Each connection has a `connectionName` (`""` is the
default connection); names do not repeat in the project.

```nuclear
// Global configuration: connections and services of the whole app, and how the local database is kept
// (encrypted = true is the default; a component's config may set `local` for the tables of its own models).
appConfig ProjectConfig
  local: LocalDatabase = LocalDatabase(encrypted = true)
  connections: Connection[] = [
    Http(
      baseUrl = "https://rickandmortyapi.com/api/",
      connectTimeout = Duration(seconds = 5),
      receiveTimeout = Duration(seconds = 3),
      interceptors = [
        SessionInterceptor(),
        EventInterceptor(events = { "force_logout": () => ForceLogout() }),
        HttpLogInterceptor(),
      ],
    ),
    WebSocket(connectionName = "live", uri = "wss://example.com/live"),
  ]
  globals: Global[] = [
    Events(),
    SessionManager(timeout = Duration(minutes = 30)),
    Acl(inherits = { "admin": ["fan"] }),
    NetworkManager(),
    // assets/i18n/<locale>/<component>.json; with remote = RemoteDictionaries(url = "https://...") the
    // dictionaries are downloaded by version and win over the app's
    Translations(locales = ["en", "es"], fallback = "en"),
  ]
```

Output (`lib/config/project_config.dart`, without the imports, which are written automatically):

```dart
/// Global configuration: connections and services of the whole app, and how the local database is kept
/// (encrypted = true is the default; a component's config may set `local` for the tables of its own models).
class ProjectConfig extends AppConfig {
  @override
  final LocalDatabase local = LocalDatabase(encrypted: true);
  @override
  final List<Connection> connections = [
    Http(
      baseUrl: 'https://rickandmortyapi.com/api/',
      connectTimeout: Duration(seconds: 5),
      receiveTimeout: Duration(seconds: 3),
      interceptors: [
        SessionInterceptor(),
        EventInterceptor(events: {'force_logout': () => ForceLogout()}),
        HttpLogInterceptor(),
      ],
    ),
    WebSocket(connectionName: 'live', uri: 'wss://example.com/live'),
  ];
  @override
  final List<Global> globals = [
    Events(),
    SessionManager(timeout: Duration(minutes: 30)),
    Acl(inherits: {'admin': ['fan']}),
    NetworkManager(),
    Translations(locales: ['en', 'es'], fallback: 'en'),
  ];
}

// assets/i18n/<locale>/<component>.json; with remote = RemoteDictionaries(url = "https://...") the
// dictionaries are downloaded by version and win over the app's
```

- `Http(...)` accepts dio's options: `baseUrl`, `connectTimeout`, `receiveTimeout`, `sendTimeout`, `headers`,
  `queryParameters`, `contentType`, `responseType`, `followRedirects`, `maxRedirects`, `persistentConnection`,
  `validateStatus`, `interceptors`.
- `WebSocket(connectionName, uri, headers, protocols, pingInterval, interceptors)`: outside development,
  `wss://` (`ws://` is not encrypted).
- Interceptors: a class that extends `HttpInterceptor` and overrides `onRequest(request: RequestOptions)`,
  `onResponse(response)` or `onError(error: HttpError)`. Included: `SessionInterceptor` (the session token,
  and ending the session on a 401) and `HttpLogInterceptor`.
- `globals`: `Events()`, `SessionManager(timeout = ...)`, `NetworkManager()` or an own class that extends
  `Global`.
- `logColor` (only in `config`): the color of the component's logs (§6.17).
- `local: LocalDatabase = LocalDatabase(encrypted = true)`: how the local database (§6.2, ADR-0096) is kept.
  `encrypted` (default `true`) is AES-256 with a key generated once and kept in the device's secure storage; in a
  `config` it applies to the tables of that component's own models and wins over the project's. Changing it after
  the first run needs the tables cleared: a table is read with the cipher it was written with.

### 6.2 Models

A model is only its definition. The transpiler writes the immutable class with `fromJson`/`toJson`
(json_serializable; `dragonfly build` runs `build_runner`). A field `name?: T` is optional.

```nuclear
// Business error of the component: dragonfly builds it with the failure message.
CharacterError
  message: string
```

Output (`lib/components/characters/domain/models/character_error.dart`, without the imports, which are written automatically):

```dart
part 'character_error.g.dart';

/// Business error of the component: dragonfly builds it with the failure message.
@JsonSerializable(explicitToJson: true)
class CharacterError {
  const CharacterError({required this.message});

  factory CharacterError.fromJson(Map<String, dynamic> json) => _$CharacterErrorFromJson(json);

  final String message;

  Map<String, dynamic> toJson() => _$CharacterErrorToJson(this);

  @override
  bool operator ==(Object other) =>
      identical(this, other) ||
      other is CharacterError &&
          message == other.message;

  @override
  int get hashCode => Object.hashAll([message]);
}
```

An error type of a dragonfly `Result` (repositories, guards) has a field `message: string`: dragonfly builds it
with `E(message = ...)`. A `Result<string, T>` gets the message directly.

**Generic models.** A shape that repeats with another model inside (an API page) is declared once with a type
parameter and each use says which one: `Page<Character>`, `Page<Episode>`. It goes in `shared/models/` so every
component sees it.

```nuclear
// A page of an API list: always info + results; only the model of each result changes
// (Page<Character>, Page<Episode>...). It lives in shared/: every component uses it.
PageInfo
  count: int
  pages: int
  next?: string
  prev?: string

Page<T>
  info: PageInfo
  results: T[]
```

Output (`lib/shared/models/page.dart`):

```dart
part 'page.g.dart';

/// A page of an API list: always info + results; only the model of each result changes
/// (Page<Character>, Page<Episode>...). It lives in shared/: every component uses it.
@JsonSerializable(explicitToJson: true)
class PageInfo {
  const PageInfo({required this.count, required this.pages, this.next, this.prev});

  factory PageInfo.fromJson(Map<String, dynamic> json) => _$PageInfoFromJson(json);

  final int count;
  final int pages;
  final String? next;
  final String? prev;

  Map<String, dynamic> toJson() => _$PageInfoToJson(this);

  @override
  bool operator ==(Object other) =>
      identical(this, other) ||
      other is PageInfo &&
          count == other.count &&
          pages == other.pages &&
          next == other.next &&
          prev == other.prev;

  @override
  int get hashCode => Object.hashAll([count, pages, next, prev]);
}

@JsonSerializable(explicitToJson: true, genericArgumentFactories: true)
class Page<T> {
  const Page({required this.info, required this.results});

  factory Page.fromJson(Map<String, dynamic> json, T Function(Object? json) fromJsonT) =>
      _$PageFromJson(json, fromJsonT);

  final PageInfo info;
  final List<T> results;

  Map<String, dynamic> toJson(Object? Function(T value) toJsonT) =>
      _$PageToJson(this, toJsonT);

  @override
  bool operator ==(Object other) =>
      identical(this, other) ||
      other is Page &&
          info == other.info &&
          listEquals(results, other.results);

  @override
  int get hashCode => Object.hashAll([info, Object.hashAll(results)]);
}
```

The repository reads each result with the `fromJson` of the parameter's model, without writing anything else:
`getPage(page: int) Result<CharacterError, Page<Character>>` decodes with
`Page<Character>.fromJson(json, (o) => Character.fromJson(...))`. A model field can also be generic
(`page: Page<Character>`), and a model can implement interfaces (`ApiFailure > Exception` gives

A `converter` has only `fromJson(json: J) T` and `toJson(value: T) J`; the types of `JsonConverter<T, J>` come
from the signature of `fromJson`. It can be in any folder and the models of every component use it. Generated
tests ask a field with a converter for its JSON through that converter
(`const DateConverter().toJson(DateTime(2000))`). For a type the tests cannot invent (not a basic type nor
`DateTime`), the converter gives its own value with `sample() T`
(`const UriConverter().toJson(const UriConverter().sample())`); without it, the field gets `null`.

`Result<E, T>` is written in Dart as fpdart's `Either<E, T>` (`Ok` → `Right`, `Err` → `Left`), so the
generated code and your own Dart code (for example tests) use the same API: `match`, `fold`, `map`,
`flatMap`, `mapLeft`, `getOrElse`.

**A model with a key has a local table** (ADR-0096). `@primary` on a field (`@primary(generated = true)`: a key the table
gives when a row is saved with it null, the field is `T?`) gives the model a table in the app's local database,
with the same words as a backend entity; `@created` and `@updated` (a `DateTime?` or `string?`) are stamped by
the table. The JSON name of the field (`@key`) is the column, and `@entity("characters")` on the model names the
table (default: the model's name in snake_case); the other column options of a backend entity (`@column`) have no
meaning in the device's document store. One key per model; a generic model has no table. The model gets
`static final LocalTable<Character> table` (§6.3, [dragonfly.md](dragonfly.md) §3.2) and `registerDragonfly`
registers it with its component, whose `config` may say how it is kept (§6.1 `local`). The database is the same on
Android, iOS, Linux, macOS, Windows and web.

### 6.3 `repository`

Each method without a body and with an http decorator is a call to the backend. The return type says how the
response is decoded (a model, a list of models, a value or `void`); methods are always asynchronous (called
with `~`). With `saveLocal = true`, a GET that answers a model with `@primary` (or a list of them) also keeps
its rows in the local database and gets a twin `<method>AsLocal()`; a method with a body queries the local
tables (`local<Character>()`).

```nuclear
// Repository: each method is an http call. The path is appended to the connection's baseUrl;
// `:id` takes the value of the `id` parameter, and the other parameters go to the query (GET) or the body.
// saveLocal: a GET that answers a Character (or a list) saves it in the local table and gets getOneAsLocal(id) /
// getManyAsLocal(ids), which answer the same from the device, without a request.
@repository(path = "character", saveLocal = true)
repository CharacterRepository
  @get(path = ":id")
  getOne(id: int) Result<CharacterError, Character>

  @get(cache = true, ttl = Duration(minutes = 10))
  getPage(page: int) Result<CharacterError, Page<Character>>

  // the API answers 404 when no character has that name
  @get
  search(name: string) Result<CharacterError, Page<Character>>

  @get(path = ":ids")
  getMany(@path ids: string) Character[]

  @post(retry = 1)
  save(character: CharacterParams) Result<CharacterError, Character>

  // the characters fetched so far, newest first: a query on the local table, no request
  recent(count: int) Character[]
    ~local<Character>().orderBy("created", desc = true).limit(count).getMany()
```

Output (`lib/components/characters/data/character_repository.dart`, without the imports, which are written automatically):

```dart
/// Repository: each method is an http call. The path is appended to the connection's baseUrl;
/// `:id` takes the value of the `id` parameter, and the other parameters go to the query (GET) or the body.
/// saveLocal: a GET that answers a Character (or a list) saves it in the local table and gets getOneAsLocal(id) /
/// getManyAsLocal(ids), which answer the same from the device, without a request.
class CharacterRepository extends Repository {
  CharacterRepository() : super(path: 'character', saveLocal: true);

  Future<Either<CharacterError, Character>> getOne(int id) => attempt(
        () => send(
          HttpMethod.get,
          ':id',
          params: {'id': id},
          local: 'CharacterRepository.getOne',
          decode: Decode.one(Character.fromJson),
        ),
        Right.new,
        (e) => Left(CharacterError(message: e.message)),
      );

  /// What `getOne` last answered for these arguments, from the local database: no request.
  Future<Either<CharacterError, Character>> getOneAsLocal(int id) => attempt(
        () => recall(
          'CharacterRepository.getOne',
          ':id',
          params: {'id': id},
          decode: Decode.one(Character.fromJson),
        ),
        Right.new,
        (e) => Left(CharacterError(message: e.message)),
      );

  Future<Either<CharacterError, Page<Character>>> getPage(int page) => attempt(
        () => send(
          HttpMethod.get,
          '',
          params: {'page': page},
          cache: Cache(ttl: Duration(minutes: 10)),
          cacheName: 'CharacterRepository.getPage',
          decode: Decode.one((json) => Page<Character>.fromJson(json, (o) => Character.fromJson(o as Map<String, dynamic>))),
        ),
        Right.new,
        (e) => Left(CharacterError(message: e.message)),
      );

  void purgeGetPage() => purgeCache('CharacterRepository.getPage');

  /// the API answers 404 when no character has that name
  Future<Either<CharacterError, Page<Character>>> search(String name) => attempt(
        () => send(
          HttpMethod.get,
          '',
          params: {'name': name},
          decode: Decode.one((json) => Page<Character>.fromJson(json, (o) => Character.fromJson(o as Map<String, dynamic>))),
        ),
        Right.new,
        (e) => Left(CharacterError(message: e.message)),
      );

  Future<List<Character>> getMany(String ids) => send(
        HttpMethod.get,
        ':ids',
        pathParams: {'ids': ids},
        local: 'CharacterRepository.getMany',
        decode: Decode.list(Character.fromJson),
      );

  /// What `getMany` last answered for these arguments, from the local database: no request.
  Future<List<Character>> getManyAsLocal(String ids) => recall(
        'CharacterRepository.getMany',
        ':ids',
        pathParams: {'ids': ids},
        decode: Decode.list(Character.fromJson),
      );

  Future<Either<CharacterError, Character>> save(CharacterParams character) => attempt(
        () => send(
          HttpMethod.post,
          '',
          params: {'character': character},
          retry: 1,
          decode: Decode.one(Character.fromJson),
        ),
        Right.new,
        (e) => Left(CharacterError(message: e.message)),
      );

  /// the characters fetched so far, newest first: a query on the local table, no request
  Future<List<Character>> recent(int count) async {
    return await local<Character>().orderBy('created', desc: true).limit(count).getMany();
  }
}
```

| Decorator | Where | Arguments |
|---|---|---|
| `@entity` | model | `@entity("table")`: the name of the model's local table (default: its name in snake_case) |
| `@repository` | class | `path`: added to the connection's `baseUrl`; `connection`: the `connectionName` of the connection (default `""`); `saveLocal = true`: every `@get` that answers a model with `@primary` (or a list) saves its rows locally and gets `<method>AsLocal()` |
| `@get` `@post` `@put` `@patch` `@delete` | method | `path` (added to `@repository`'s; `:name` takes the value of a parameter), `headers` (map), `cache = true`, `cacheKey`, `ttl` (default 5 min), `retry` (extra attempts); on `@get`, `local = true` (what `saveLocal` does, for this method) |
| `@path` `@query` `@body` | parameter | the parameter goes to the path, the query or is the body |

- An undecorated parameter goes to the path if the path has `:name`; otherwise to the query (`@get`,
  `@delete`) or to the body (`@post`, `@put`, `@patch`: a single parameter is the body as it is; several form
  an object).
- A method that returns `Result<E, T>` turns the failure into `Err(E(message = ...))`; any other throws
  `HttpError` (`message`, `statusCode`, `timeout`, `offline`).
- `cache = true`: the response of each combination of arguments is kept until its `ttl`, and the repository
  gets `purge<Method>()` and `purgeCache(key)`. Ending the session deletes the whole cache.
- Retries: `@get`, `@put` and `@delete` retry transient failures twice (timeout, no connection, 5xx) with
  growing waits (300 ms, 600 ms...); `@post` and `@patch` only with `retry`, because repeating a write can
  duplicate it.
- **Local database** (`saveLocal = true` on the repository, or `local = true` on a `@get`; ADR-0096): the
  decoded rows of a GET that answers a model with `@primary` (or a list of them; not `Page<Character>`, which has
  no key) go to the model's table, encrypted on the device, and the call remembers which rows it answered. The
  twin `<method>AsLocal()` has the same signature and return type and answers those rows as they are now, without
  a request; with nothing saved for those arguments it is `Err(E(message = ...))`, or throws `NotFound` when the
  method does not return `Result`. The generated tests call each twin after its request. A GET that answers a
  model without `@primary` fails at its first call with the fix in the message.
- `local<Character>()` is the model's table (`LocalTable`, also `Character.table`): `find(id)`, `findAll()`,
  `save(x)`, `saveAll(xs)`, `remove(id)`, `clear()`, and a query built as in a backend repository:
  `where({ "status": "Alive", "id": gt(10) })` (equality, or `gt`, `gte`, `lt`, `lte`, `ne`, `like`, `ilike`,
  `oneOf`, `between`; a plain `null` is "is null", `ne(null)` "is not null"), `orderBy("name", desc = true)`,
  `limit(n)`, `offset(n)`, run by `getOne()` (`Result<NotFound, T>`), `getMany()`, `paginate(page, size)`
  (`Page<T>`, written `PageOf<T>` in Dart: Flutter's own `Page` is the Navigator's; a model of the app named `Page`
  keeps its name), `count()`, `exists()`, `update({...})`, `delete()`. A backend's paged answer (`Page<Task>` of a
  contract) is read into the same class. A repository method with a body writes its query on it (`recent` above); a
  repository may have only such methods (100 % local). The tables are in memory in tests.

#### Navigation

Only views navigate (`N0301`, §4), with the screen and not with the address:

| Writing | What it does |
|---|---|
| `context.goTo(CharacterDetailScreen(id = 7))` | shows the screen instead of the current stack; its address comes from its route (`/characters/7`) |
| `result = ~context.pushTo(PickerScreen())` | shows it on top of the current one; `result` is what that screen gives back with `goBack` |
| `context.goBack(value)` | closes the current screen |
| `navigator.goBranch(1)` | (in a `shell`'s widget) changes tab |

The screen opened with `goTo`/`pushTo` is that same object. Opened from an address (a link, the web browser),
its parameters are read from the route and the query according to their type (`string`, `int`, `double`,
`boolean`; a parameter with a default takes it if missing). A parameter of another type (a model) only arrives
with `goTo`/`pushTo`.

A route whose address starts with the address of another route is nested in it (the longest one; never in `/`):
`/characters/:id` goes inside `/characters`, and `/characters/:id/episodes` inside `/characters/:id`. Going to it
stacks its parent below, also from a link, so back (`goBack`, the system's back button) returns to the parent.
The parent is built from the address, so its parameters must be in its route. In a `shell` tab the nested
routes stay in that tab and its stack.

#### Splash

A splash has two parts that look the same, and the user does not notice the step from one to the other:

1. **The native screen**, which the platform shows while Flutter starts and runs `startDragonfly()`. It comes
   from `@splash(color, image)` on the splash screen: `color` (required) is the background and `image`, an
   image of `assets/` at 4x size (512 px looks like 128 px). With it, the project generates
   `flutter_native_splash.yaml` and `dragonfly build` runs `flutter_native_splash:create`, which writes the
   native splash of Android (also Android 12+), iOS and web. On Linux and Windows the window opens only with
   Flutter's first frame, so the first thing seen is already the `SplashScreen`. `startDragonfly()` removes
   the native splash on the app's first frame, whatever its route (a direct link on web also removes it). A
   project has a single `@splash`, and its route becomes the initial one (`buildRouter`).
2. **`SplashScreen`** (from the package, `spec/dragonfly.md` §6), the widget of that screen: it shows `child`
   for at least `minDuration` (3 s by default) while `onLoad` prepares the app (call the backend, fill the
   local database) and then goes to `next` with the router (`goTo`: "back" does not return to the splash). If
   `onLoad` takes longer than `minDuration`, the splash stays until it finishes. If it fails, it shows
   `onError(context, error, retry)` (`retry` runs it again); without `onError`, the error is logged and the
   app continues to `next`. It uses a single timer: it does not poll nor draw its own frames. `next` needs
   `@screen(route = ...)`, and the screen
   that holds it is not called `SplashScreen` (that is the widget's name).

So there is no jump, `child` uses the same background and the same image, at the size the native one shows.
On Android 12+ the system crops the image into a circle: the image for it goes centered, with a margin.


### 6.10 `event` and global events

A global event is a typed message: whoever publishes it does not know who listens. The event manager
(`Events`, in the `globals` of the project config) is available in the whole app and has two operations:

| Writing | What it does |
|---|---|
| `Events.publish(Event(...))` | publishes the event; also from a background isolate or another Flutter engine of the app, like a workmanager task (it reaches the main one) |
| `sub = Events.subscribe<Event>((e) => ...)` | gets each event of that type; `sub.cancel()` ends it |

Delivery is **on demand**: a screen gets an event only while it is the visible one. The others do nothing;
when they are shown again they get the last event of each type that arrived while they were hidden. Global
components (`component`, §6.11) always get it.

| In a view | What it does |
|---|---|
| `EventBuilder<Event>(builder = (context, e) => ...)` | rebuilds with the last event (`null` until the first) |
| `EventListener<Event>(onEvent = (context, e) => ..., child = ...)` | runs `onEvent` with each event (navigate, show a popup) |
| `GlobalEvents<Auth>(sessionStarted = (auth) => ..., sessionEnded = (e) => ..., onSessionEnded = (e) => ...)` | shows `sessionStarted` with the session's data while there is one, and `sessionEnded` otherwise (`e` is `null` if none ended); `onSessionEnded` runs once every time the session ends |

Included events: `SessionStarted<T>(data)`, `SessionEnded(expired)` and `ForceUpdate(minVersion)`. The backend
publishes events with a header of any response: with
`EventInterceptor(events = {"force_logout": () => ForceLogout()})` in the `interceptors` of a connection, a
response with `x-app-event: force_logout` publishes `ForceLogout()` (`header` changes the header's name).

```nuclear

// (EventInterceptor in project_config).

  reason?: string
```

(`Events.decoder("ForceLogout", ForceLogout.fromJson)`). So the fields of an event are JSON types: basic types,
`DateTime`, enums, models and lists of them (`@key` and converters work as in a model).

### 6.12 Session

`SessionManager` (in the `globals` of the project config) creates, stores and ends the session. The session is
stored in secure storage (Keychain on iOS and macOS, encrypted with Keystore on Android, libsecret on Linux),
survives restarting the app and ends by itself after `timeout` without activity or when `expiresAt` arrives.

| Writing | What it does |
|---|---|
| `~session.start(data, token = ..., roles = [...], permissions = [...], expiresAt = ...)` | starts the session with `data` (a model, a text); `token` goes on each request (`SessionInterceptor`); publishes `SessionStarted` |
| `session.get<Auth>()` | the session's data |
| `session.active`, `session.session` | whether there is an active session; the session (`token`, `roles`, `permissions`, `expiresAt`) |
| `~session.set("key", value)`, `session.value<T>("key")`, `~session.remove("key")` | values of the session (text, numbers, lists, maps), stored with it |
| `~session.destroy()` | deletes it from the device, empties the response cache and publishes `SessionEnded` |

`SessionInterceptor` adds `Authorization: Bearer <token>` and ends the session on a 401. A model stored as
data is read again when the app restarts with its `fromJson` (the transpiler registers it).

```nuclear
// Starts the session: the token goes in every request and the ACL checks the roles. session.start publishes
// SessionStarted, and every screen with GlobalEvents or @screen(loggedIn) is notified.
usecase LoginUseCase
  (repository: AuthRepository, session: SessionManager)

  exec(user: string, pass: string) Result<AuthError, Auth>
    auth = ~repository.login(LoginParams(user = user, pass = pass))
    ~session.start(auth, token = auth.token, roles = auth.roles)
    // the token is masked in the log: ***
    Log.i("session started", data = { "user": user, "token": auth.token })
    Ok(auth)
```

Output (`lib/components/session/domain/usecases/login_usecase.dart`, without the imports, which are written automatically):

```dart

/// SessionStarted, and every screen with GlobalEvents or @screen(loggedIn) is notified.
class LoginUseCase {
  LoginUseCase(this.repository, this.session);

  final AuthRepository repository;
  final SessionManager session;

  Future<Either<AuthError, Auth>> exec(String user, String pass) async {

    if (authResult case Left(:final value)) return Left(value);

      data: {'user': user, 'token': auth.token},
      at: 'session › usecase › LoginUseCase.exec · components/session/domain/usecases/login_usecase.nuc:10',
    );
    return Right(auth);
  }
}
```

### 6.13 ACL and `guard`

Access rules are written on the screens (`@screen(acl = ...)`) and on the use cases (`@acl(...)`, §6.4). The
session brings the roles and permissions `start` received; everything that is not allowed is denied. `Acl` (in
the `globals`) declares role inheritance and the permissions of each role:

```nuclear
Acl(inherits = {"admin": ["fan"]}, permissions = {"fan": ["favorites.read"]})
```

| Rule | Passes if |
|---|---|
| `roles: [...]` | the session has one of those roles, or one that inherits it (`admin` inherits `fan`) |
| `permissions: [...]` | the session has all of them: its own and its roles' |
| `guards: [Guard, ...]` | the `canActivate()` of each guard returns `true` |

The session's roles and permissions are computed once per session, and access to each screen is kept until the
session changes. In a view, `AclBuilder(screen = FavoritesScreen, child = ..., fallback = ...)` (or with
`roles`, `permissions`, `guards`) shows `child` only if the session passes the rule, and
`Acl.can(roles = [...])` / `Acl.canOpen(Screen)` answer the same.

A `guard` is an own check with its dependencies injected (a single method `canActivate`, `N0215`):

```nuclear
// Guard: a custom access check, like NestJS CanActivate.
guard PremiumGuard
  (session: SessionManager)

  canActivate() boolean
    session.value<boolean>("premium") != false
```

Output (`lib/shared/guards/premium_guard.dart`, without the imports, which are written automatically):

`canActivate` can wait: with `~` in its body (ask the server) it returns `Future<bool>`. The router and

too (`Guards.verify`), and `~Acl.check(guards = [...])` is the version of `Acl.can` that waits. `Acl.can`,
`Acl.canOpen` and a use case that is not async are synchronous: with an async guard they throw an error that
says so.

### 6.14 Forms: `form` and `formmanager`

The format validations of a form (required, email, length, regex, two fields matching) belong to
**presentation**, not the domain: they depend on the screen (signing up and editing the profile validate the
same user differently), they show while the user types and their messages are UI texts. That is why they live
in a form model and its form manager, in `presentation/<screen>/`, and do not clutter the business
`statemanager` nor the use cases. Business rules (the email is not registered yet, there is stock) stay in the
domain: the form manager asks the component with `@validate`, like any state manager, and the use case checks
them again when it runs.

| Piece | Where | What it is |
|---|---|---|
| `form` (form model) | `presentation/<p>/forms/` (kind by folder) | the fields and their rules, like zod or class-validator |
| `formmanager` | `presentation/<p>/managers/` | the form's state (`FormManager<F>`, a Cubit): values, errors, remote validations |
| `DragonflyForm` + fields | the screen | the widgets; each field is bound to the form model's **by its name** |

Rules of a field of the form model (decorators on the field; all accept `message = ...`):

| Decorator | Validates |
|---|---|
| `@required` | not empty (a `boolean` must be `true`: accepting the terms) |
| `@email`, `@url` | format |
| `@minLength(n)`, `@maxLength(n)` | length of the text |
| `@min(n)`, `@max(n)` | value of a number |
| `@pattern("regex")` | regular expression (`\\d` is written with two backslashes) |
| `@matches("other")` | equal to the field `other` (repeating the password) |

An `int` or `double` field also validates that it is a number; an empty optional one (`field?: T`) passes every
rule except `@required`. A `message` is a key of the dictionary (§6.16) or the text; without `message`,
Dragonfly's text in the app's language. A field's error shows when the user leaves it or when the form is sent.

```nuclear

  @required
  @minLength(3)
  user: string

  @required
  @minLength(5, message = "session.login.shortPass")
  pass: string
```

### 6.15 Dialogs and popups

`DragonflyDialog` is a dialog in three parts, like a Bootstrap modal: **header** (the icon of its type,
`header` and a close button), **body** (`child`) and **footer**. It adapts to what it receives:

| Receives | Shows |
|---|---|
| only `child` | a message: icon, close button and the text |
| `header` | the title next to the icon |
| `onCloseButton` | the footer with the Close button (closes the dialog after the lambda) |
| `onAccept` | the footer with Close and Accept; `show` returns `true` if it was accepted |
| `footer` | that widget in the footer, with Close (and Accept with `onAccept`) |
| `onClose` | the lambda runs when it closes, in any way |
| `autoClose = Duration(seconds = 3)` | closes by itself |
| `size = DragonflyDialog.small` / `medium` / `large` | the width (default `medium`) |
| `color`, `icon` | replace the type's in this dialog |

Types: `DragonflyDialog(...)` (= `.info`), `DragonflyDialog.success`, `.warning`, `.danger`, each with its icon
and color, taken from the app's theme (info = `primary`, danger = `error`, success green, warning amber).

### 6.16 Translations

The app's texts are in JSON dictionaries, **one per component and per language**, in
`assets/i18n/<locale>/<component>.json` (what belongs to the whole app, in `shared.json`). A text's key is
`<file>.<path inside the file>`; `{name}` is replaced with the arguments of `tr`:

```json
{
  "login": { "title": "Login", "hi": "Hi {name}" }
}
```

`assets/i18n/en/session.json` → `"session.login.title".tr()`, `"session.login.hi".tr({"name": auth.name})`.

So each dictionary is small and is deleted with its component; in memory there are only the current language
and the fallback one (`fallback`), in a flat map (each `tr` is a lookup). No third-party libraries: the files
are read with Flutter's `AssetManifest`, on every platform. A missing text is looked up in the `fallback`, then
in Dragonfly's (`dragonfly.dialog.accept`, `dragonfly.form.required`...; a `dragonfly.json` dictionary
replaces them) and otherwise the key is shown.

`Translations` goes in the `globals` of the appConfig (§6.1). It chooses the stored language, else the
device's, else `fallback`:

```nuclear
Translations(locales = ["en", "es"], fallback = "en")
```

In `main.nuc`, `MaterialApp` gets `locale = Translations.locale`, `supportedLocales =
Translations.supportedLocales` and `localizationsDelegates = Translations.delegates` (the texts of Flutter's
widgets). `~Translations.use("es")` changes the language, remembers it for the next start and rebuilds the app
keeping its state.

**Remote dictionaries.** With `remote = RemoteDictionaries(url = "https://api.example.com/i18n")` the texts
change without publishing the app. The server has `manifest.json` and one file per language and dictionary:

```json
{ "version": "7", "locales": { "es": ["session", "shared"], "en": ["session", "shared"] } }
```

`<url>/7/es/session.json`. At start, the app immediately uses the last downloaded version and in the
background asks for `manifest.json`; if the version is new, it downloads its files (only those of `locales`),
stores them in their own folder `<version>/<locale>/<file>.json`, marks that version as the current one when
it finishes (an interrupted download is never used), deletes the previous ones and rebuilds the app. What was
downloaded wins over what is in the app, key by key. On Android, iOS, macOS, Linux and Windows it is stored in
the app's support folder; on web, in `localStorage` with the same paths. Without network the stored ones keep
being used.
`~Translations.refresh()` looks for a new version on demand.

### 6.17 Logs

`Log.d` (debug), `Log.i` (info), `Log.s` (success), `Log.w` (warning) and `Log.e` (error) write to the console a
block with a breadcrumb: component › kind › Class.method, the time, the message, the data and, at the foot, the
`.nuc` file and its line. Nuclear writes the breadcrumb in each call (`at`, a constant text: it costs nothing at
run time); it is not written by hand.

| Method | Level and color | When to use it | In release |
|---|---|---|---|
| `Log.d` | `DEBUG`, blue | details for the developer while building: values, steps, requests | no |
| `Log.i` | `INFO`, cyan | something normal worth knowing: a screen opened, a session started | no |
| `Log.s` | `SUCCESS`, green | an operation finished well: data loaded, form saved | no |
| `Log.w` | `WARNING`, yellow | something unexpected the app survives: a slow response, a retry, a default value | yes |
| `Log.e` | `ERROR`, red | something failed; with `error = e, stackTrace = s` it shows the exception and the exact line (`▶`, the only thing that blinks) | yes |

All of them get the message and, optionally, `data = ...` (any value, as JSON).
`Log.debug/info/success/warn/error` are the same with long names.

- The frame (thick, 96 columns) and the level label carry the vivid color of Bootstrap's dark-mode alerts:
  `DEBUG` primary, `INFO` info, `SUCCESS` success, `WARNING` warning and `ERROR` danger, in bold and without a
  background. The message contrasts with them: almost white, with a light tint in `WARNING` and `ERROR`. A
  blank line separates each block. Every color is from the xterm-256 palette (24-bit colors look gray in some
  debug consoles, like VS Code's).
- In the breadcrumb, the component has its color: always the same for the same name, or the `logColor` of its
  `config` (`LogColor.mint`, `sky`, `peach`, `lemon`, `rose`, `aqua`, `lime`, `indigo`); Dragonfly's own logs
  are purple. The rest uses code colors (VS Code Dark+): kind, Class, method, and in `data` keys, strings and
  numbers. The message keeps the console's color.
- Only the exact place of an error blinks: in the stack of `Log.e` and of exceptions, the app's first line (not
  Dart's, Flutter's nor Dragonfly's), marked with `▶`. It is ANSI's slow blink; the console decides its speed.
- Outside `components/` the component is `app`; the package's logs say `dragonfly › http`,

- `data` is any value; in a map, `token`, `password`, `authorization`, `secret` and `cookie` are masked

- The long names `Log.debug/info/success/warn/error` also exist.
- Flutter exceptions (build, layout, platform messages...) come out with their own format: a double frame

  blinks), Flutter's dimmed and the Dart SDK's hidden (`· 2 Dart SDK frames`). If the same error repeats (an

### 6.20 Genkit (plugin `genkit`)

Genkit Dart in the app (ADR-0092): `plugins(genkit = true, <provider> = true)` in `config.nuc`, and the provider among
the connections of the project config. Providers (one plugin each; the CLI adds only the enabled ones):
`FirebaseAI(model)` (plugin `firebaseAI`: Firebase AI Logic, App Check, no key in the app; the app configures
Firebase), `GoogleAI(model, embedder, apiKey)` (`googleAI`, GEMINI_API_KEY), `VertexAI(model, embedder, projectId,
location)` (`vertexAI`), `OpenAI(model, embedder, apiKey, baseUrl)` (`openAI`; `baseUrl` reaches any OpenAI-compatible
server, a local Ollama: `http://localhost:11434/v1`), `Anthropic(model, apiKey)` (`anthropic`). `connectionName`
names a second one (`model = "fast"` in a kind).

```nuclear
  ]
```

| Kind | Nuclear | What it is |
|---|---|---|
| `tools` | `tools NoteTools(deps)` + methods with a doc comment | Genkit tools: the doc comment is the description, the parameters the JSON schema; a method without one is a helper |
| `chat` | `chat Assistant(notes: NoteTools)` + `prompt`, `model` | a conversation with memory: `~chat.send(text)`, `chat.stream(text)`, `ChatController(chat)` for a screen; a new one per `inject` |
| `flow` | `flow Summarize(deps)` + `run(input: I) O` | a Genkit flow (traces, Developer UI): `~summarize(text)`; `~generateObject<Summary>(prompt)` answers a model of the app |
| `remote` | `@remote("https://server") remote StoryFlows` + `@flow("path")` / `@stream("path")` methods without body | flows of a Genkit server (Node, Go, Python, Dart), typed |
| `knowledge` | `knowledge Faq(deps)` + `documents() string[]` | texts searched by meaning (embeddings): `~faq.search(q, k = 4)`, `~faq.context(q)` for a prompt (RAG) |

The generated `lib/dragonfly_genkit.g.dart` (only with the plugin) turns each provider into its plugin and registers
the schema of every model of the app (from its fields) for flows and structured output; `startDragonfly` calls
`startGenkit()` and the injector gets the kinds (a chat as a factory). Tests: `startFakeGenkit(["answer"])` (a model
with fixed answers and an embedder without network). Example: `examples/examples-flutter-dialect/genkit-assistant`.

## 8. Tests


Tests are written in Nuclear, in `test/` (unit, states, widgets) and `integration_test/` (the real app on a
device). They use [mocktail](https://pub.dev/packages/mocktail) for mocks and
[bloc_test](https://pub.dev/packages/bloc_test) for states. `dragonfly test` runs them;
`dragonfly test --integration -- -d <device>` runs the integration ones.

A file of `test/` is a group (kind `tests`, without a header word). Before each test, the app starts as in
`main` but without network nor device (`DragonflyTest.start`): http connections answer what the test says (404
if it says nothing), the session lives in memory and the network is connected.

| Inside a group | What it is |
|---|---|
| `@mock([CharacterRepository])` (on the group) | a mocktail mock of that class in the injector, instead of the real one |
| `Class.method()` | the injector's instance (the mock, or the real class): `GetPageUseCase.exec(1)` |
| `setUp()`, `tearDown()`, `setUpAll()`, `tearDownAll()` | methods without a decorator: run before or after the tests |
| `@test("description")` | a unit test |
| `@states("description", expect = [...], seed = ..., wait = ..., skip = n)` | a test of a statemanager (bloc_test): the parameter is the manager (from the injector) and the body, what it does; `expect`, the states it emits |
| `@widget("description")` | a widget test: the parameter is the `WidgetTester` |
| `@offline` (on the group) | the network is disconnected (`NetworkManager`) |
| a `Result` | does not propagate: it is compared with `isOk`, `isErr`, `isOkWith(value)`, `isErrWith(error)` |
| `when(() => X.method(...)).thenReturnAsync(Ok(...))` | what the mock answers (`thenReturn` for non-async methods; `verify(() => ...)` checks a call) |

```nuclear
// Tests of the characters component: the repository is a mock (mocktail); everything else is the real code.
```

## 11. The `dragonfly` CLI

The CLI is the `dragonfly` repository. Names are written in any form (`user_profile`, `UserProfile`) and normalized.

```sh

                                             # the other commands start with a line with the logos
dragonfly new <name> [-p mobile|backend|web] [-d flutter|fastapi|nestjs|react] [--org com.example]
                                            # (n) new project of a platform (ADR-0093): mobile/flutter gets its
                                            #     Flutter app in build/app; backend/fastapi|nestjs and web/react
                                            #     only their .nuc, built with `nuclear build .` and the dialect's
                                            #     [toolchain] (install/run/test); `check` delegates to `nuclear check .`
dragonfly code                               # opens the project in VS Code

dragonfly build [apk|appbundle|ios|ipa|web|macos|linux|windows] [-- <flutter build arguments>]
```

- The project root is the folder with `main.nuc` (the current one or one above).
- `build` transpiles (it only rewrites the files that change and deletes those that no longer have a `.nuc`),
  adds to the app the packages it needs (dragonfly, flutter_bloc, fpdart, go_router, json_annotation;
  build_runner, json_serializable, mocktail, bloc_test and integration_test for tests), runs `flutter pub get`
  if the `pubspec.yaml` changed since the last one (marker `.dart_tool/nuclear_pub_get`) and `build_runner` if
  a model changed. `run`, `test` and the devices call Flutter with `--no-pub`: `build` already resolved the
  packages. It copies `assets/` to the app and declares its folders in the `pubspec.yaml`. With `@splash` it
  adds `flutter_native_splash` and runs `dart run flutter_native_splash:create` if the yaml or an image changed.
  Without changes it runs no Flutter step (it takes milliseconds), so the extension's ▷ Run button can always
  call it. It also writes the VS Code workspace.
- `build` exits with code 2 if the `.nuc` files have errors and with 1 if another step fails (pub get,
  build_runner, splash).
- `repair` is for when something fails without the `.nuc` files having errors. It runs in steps and stops at
  the first that leaves a valid app (`flutter analyze` without errors; warnings and notes do not count):
  1. `build` and `analyze`;
  2. `flutter pub get`, `build_runner` and the splash from scratch, `build` and `analyze`;
  3. `flutter clean`, `build` (with `pub get`, `build_runner` and splash again) and `analyze`.

  With errors in the `.nuc` files it stops at once with code 2: no step fixes them. Normal use (▷ Run, Ctrl+S)
  does not run it; the extensions call it only when something fails (§11.1, §11.2).
- `build` writes the line map `build/app/.dart_tool/nuclear_lines.json`: for each generated `.dart`, its `.nuc`
  and the pairs (Dart line, Nuclear line) of each statement, member, declaration and argument that takes its own
  line. A Dart line that is not in the map belongs to the previous one that is. The extensions' debuggers use it
  (§11.1, §11.2).
- `explain` reads from its input a Dart or Flutter error (the `EXCEPTION CAUGHT BY…` block, an
  `Unhandled Exception:` or a stack) and says its message, a short explanation of the frequent errors and the
  `.nuc` lines of its stack (only those of the project's code). With `--json` (used by the extensions):
  `{title, hint, frames: [{source, line, name}]}`.
- `flutter add` rejects the framework's packages (§3.1); with a third-party one it runs `flutter pub add` in the
  app (it chooses the version if none is given), writes the package with its version in `config.nuc` and runs a
  `build`, which generates its definitions if they are not in the cache (`tools/defs` with the Dart analyzer;
  the first time it runs its `dart pub get`). `flutter remove` removes it from `config.nuc` and the `build`
  removes it from the app. `pub add` and `pub remove` do the same.
- `build` starts with `config.nuc`: it takes its fields and packages to the app's `pubspec.yaml`, generates the
  missing definitions and writes `build/defs.lock`; then it transpiles. `check` uses only the definitions
  already in the cache (it does not need Flutter).
- A dialect's own commands go under its name (`dragonfly flutter add`); the other subcommands of
  `dragonfly flutter` go to Flutter as they are.
- `--project <folder>` (on any command) chooses the project instead of looking for `main.nuc`.
- Flutter is looked for in `FLUTTER`, `FLUTTER_ROOT`, the project's fvm version (`.fvm/flutter_sdk`), the PATH,
  the global fvm version (`~/fvm/default`) and the typical install folders; if it is not there, the CLI explains
  how to install it. `NUCLEAR_DIALECT_PATH` and `DRAGONFLY_PACKAGE` say where the dialects and the dragonfly
  package are (by default, those of the `install.sh` installation).
- `dragonfly code` needs VS Code's `code` command on the PATH.
- **Dragonfly devices** (`device` and `terminal-device`): the app as Flutter web in a Chromium browser (Chrome,
  Chromium, Edge, Brave or Vivaldi; `CHROME_EXECUTABLE` chooses one) with the device's screen, density, touch
  and identity (Android, iOS). Devices: `pixel7` (the default), `iphone14pro`, `iphonese`, `iphone15promax`,
  `galaxys20`, `galaxya51`, `ipadmini`, `ipadair`, `ipadpro`, `tabs7`, `responsive`, `laptop`, `desktop`.
  Several at once are numbered (device 1, 2, 3...; `device list` shows them). When they end no process is
  left: neither `flutter run` nor the browser. On Linux each device's Flutter temporary files (~500 MB: the
  compiled app and the browser profile) go to `~/.cache/dfly/<n>` and not to `/tmp`, which is often in RAM;
  they are deleted on close and when that device opens again. Memory in debug: ~1.4 GB `flutter run` with its
  compiler and ~0.9 GB the browser.
  - `device`: a window without browser bars with the device's ratio and at most 85 % of the screen height
    (smaller if it does not fit); several stay side by side. On Hyprland, Sway and i3 the window floats instead
    of filling a tile. The title says `Dragonfly device N · <device> · <app>`. The mouse is a finger. The
    terminal stays like `flutter run`'s: `r` hot reload, `R` hot restart, `q` quit; closing the window also ends it.
  - `terminal-device` (Dragonfly Terminal device): the device's screen inside the terminal, with a frame, a
    status bar and Flutter's last message. It draws with images in kitty, Ghostty and WezTerm (kitty protocol)
    and in foot, Konsole, Windows Terminal, iTerm2 and mlterm (sixel); in the others (GNOME Terminal, XFCE, LXQt,
    Alacritty, Terminal.app, the Linux console, Zed, VS Code) with colored blocks and the app's texts written as
    letters in their place, readable at any size (in truecolor, 256 or 16 colors). `--render` chooses one and
    `m` switches between them. Mouse: tap and drag, wheel = scroll, click
    right = back. Keys: `r`/`R` reload/restart, `b` back, `o` rotate, `d`/`D` another device, `m` drawing mode,
    `s` screenshot (`build/screenshots/`), `l` Flutter's log, `?` help, `q` or Ctrl+C quit; arrows, Enter and
    Tab go to the app. With a text field focused, keys are text (pasting too) and commands go with Alt
    (`Alt+r`); Esc leaves the field.
- Logos, colors and the animation only come out in a terminal: through a pipe (`dragonfly check --json`,
  `dragonfly help | grep`) the output is plain text. `NO_COLOR` removes them in the terminal too.

### 11.1 VS Code

`build/<name>.code-workspace` (opened by `dragonfly code`) has two folders: the `.nuc` files and the Flutter
app (`build/app`). With the app as a workspace folder, the Flutter extension treats it as a normal project:
device picker, run and debug (F5, debug/profile/release), hot reload and restart, DevTools, emulators and tests.

- The `dragonfly: watch` task starts by itself when the workspace opens and transpiles each saved `.nuc`; the
  Dart extension reloads the running app when the generated `.dart` files change. Saving a `.nuc` is enough to
  see the change.
- `dragonfly: build` runs before running the app. The errors of the `.nuc` files are shown by the Nuclear
  extension in the Problems panel (the tasks do not repeat them).
- Tasks: `dragonfly: watch`, `build` (Ctrl+Shift+B), `test`, `test --integration`, `analyze`.
- It recommends the Nuclear, Dart and Flutter extensions.
- `build` rewrites the workspace: changes made to it by hand are lost.

Opening only the project folder (`code .`, *File → Open Folder*) works the same, with the Nuclear extension
(0.15.0 or newer), which reads `build/<name>.code-workspace`:

- The Flutter extension finds the app in `build/app` and shows the device picker in the status bar. If the app
  is created with the window already open (the first `dragonfly build`), the Nuclear extension offers *Reload
  Window*: Flutter's only looks for apps when the window opens.
- ▷ Run / Debug in the editor bar of a `.nuc`, and F5 / Ctrl+F5 without `launch.json` (debug type
  `dragonfly`): runs `dragonfly build` and launches the app with the workspace's `<name> (debug)`
  configuration on the chosen device. The build's errors show in the *Dragonfly* panel.
- Hot reload: saving a `.nuc` of the project (Ctrl+S) with the app running runs `dragonfly build`, which
  rewrites only the `.dart` files that changed, and `flutter.hotReload`, also in the `dragonfly code` workspace.
- When something fails (0.17.0 or newer) without the `.nuc` files having errors, the extension runs
  `dragonfly repair` (§11, with a progress notice; the output goes to the *Dragonfly* panel) and, if it ends
  well, launches the app again with the same configuration:
  - the build before launching or on save fails (pub get, build_runner, splash);
  - the session ends before the app starts (event `flutter.appStarted`) and the user did not stop it (Gradle,
    Xcode or an old build fails);
  - the hot reload gives a Dart compile error (stale generated code or packages).

  If Flutter rejects the hot reload (`Hot reload was rejected`), it does a *Hot Restart*. It repairs once per
  launch: if the relaunched app fails again, it only reports it.
- Debugging the `.nuc` (0.18.0 or newer; uses the line map of §11):
  - A breakpoint in a `.nuc` (a click in the gutter, also with a condition or as a logpoint) sets a mirror
    breakpoint on the line of the generated `.dart`: the Dart debugger only stops on `.dart` files. The `.nuc`'s
    stays "unverified"; the mirror is the one that stops the app. Mirrors are rebuilt after each build (lines
    move) and when the window opens.
  - On each pause (breakpoint, step, exception) the `.nuc` opens with the pause's line highlighted, in the editor
    group left of the paused `.dart`: `.nuc | .dart | Dragonfly device` (0.23.1 or newer). If that group does not
    exist, it is created by splitting only the `.dart`'s group: the others, like the device's, keep their width.
    Variables, watch and evaluation use Nuclear's names (they are the same in Dart). Setting
    `nuclear.debug.followInNuclear`.
  - Mixed debugging (0.22.0 or newer, ADR-0076). The session is still the Dart extension's:
    - **Steps by Nuclear line:** F10 / F11 / Shift+F11 repeat the Dart step until the pause is on another `.nuc`
      line or in another call (one Nuclear line can be several Dart ones: a widget tree, a propagated `Result`).
      They apply when the pause is in code that comes from a `.nuc` and, also, the focus is on a `.nuc` or the
      pause came from a `.nuc` breakpoint. A breakpoint written in the `.dart` keeps Dart steps. The debugger bar
      has a *Step Over (Nuclear Line)* button; the usual buttons give Dart steps.
    - **Values in the `.nuc`:** when hovering a name (with the chain before it: `user.name`) and, at the end of
      each line of the paused member, the value of each local variable (setting `debug.inlineValues`).
    - **The *Nuclear Call Stack* view** in the debug panel: each frame with its place in the `.nuc` or, if it is
      code of Flutter or a package, in the `.dart`. A click opens it.
    - **Go to the same line in Nuclear / Dart** (the editor's context menu while debugging): from the `.nuc` to
      the generated `.dart` and back.
    - Names Dart writes differently are not seen by their Nuclear name: a `stateful`'s parameters are
      `widget.x`, and Dart's reserved words are escaped.
  - Dart run-time errors (setting `nuclear.debug.explainErrors`, on by default): a pause on an exception or an
    error Flutter prints is marked on its `.nuc` line (Problems panel) and opens beside it the window *Nuclear:
    runtime error* with the message, the explanation of `dragonfly explain`, the piece of the `.nuc`, the stack in
    Nuclear (each line opens the `.nuc`) and the original Dart error. The mark is cleared by the next build.

- *Nuclear workspace* (0.31.0 or newer, ADR-0099): one *Nuclear* container in the activity bar (`Ctrl+Alt+N`) with a
  vertical strip of tabs beside a pane. Every tab is a workspace of its own: the projects at the top (`Ctrl+1` …
  `Ctrl+9`; the Nuclear projects of the workspace folders, then the ones opened with *Open a Project as a Tab*,
  `Ctrl+Alt+O`, which remembers the folder without touching the VS Code workspace; each tab shows its platform with the
  dialect as a badge) and the tools at the bottom (`Ctrl+Alt+<letter>`). Switching tabs swaps the editor area: the
  editors of one are remembered and closed (an unsaved one stays open, never a save prompt), those of the other
  reopened; only the devices stay beside the code. A
  project's pane shows its files (with the Chernobyl icon theme, honouring `files.exclude`); **the actions of its
  platform are the toolbar of the editor title bar** (the row of the editor tabs, since 0.34.0): mobile Run
  `Ctrl+Alt+R`, Debug `Ctrl+Alt+G`, Hot reload `Ctrl+Alt+L`, Device, Build `Ctrl+Alt+B`, Test `Ctrl+Alt+T`, Check
  `Ctrl+Alt+C`; backend Serve, Test, Build, Check, API (its routes in the HTTP tool); web Serve, Build, Test, Check.
  Clicking a tab shows the shortcut that does the same; the toolbar tooltips show theirs. Run, Debug and Device of a
  mobile project opened as a tab first add its folder to the VS Code workspace (the Dart extension runs Flutter only
  there): the window reloads once and the action continues. A welcome page (`Ctrl+Alt+W`; at startup when no editor is open, setting
  `nuclear.workspace.welcome`) lists the projects, the tools and the keys. *Nuclear: Add the Active Project to the VS
  Code Workspace* adds a tab's folder to the explorer, search and git when wanted.
- *Nuclear HTTP* (0.29.0 or newer, ADR-0098; a workspace of its own since 0.33.0, `Ctrl+Alt+H`): its pane is the
  endpoints tree of every project of the window, by platform, project and component like the code (backend routes,
  mobile and web calls, read from `.nuclear/contract.json`), the contracts an app declares with *↓ Update*
  (`nuclear contracts update`), the OpenAPI documents of APIs that are not Nuclear (*+*), and the environment
  (`.nuclear/http.json` of the first folder: variables, headers, base urls per project or connection). Like Bruno, a
  component is an editor tab and each endpoint a tab inside it: method, url with path and query parameters, headers, a
  sample body from the model, the pretty-printed response and *copy as curl*; a component keeps its tabs when the
  workspace is left.
- *Devices* (0.33.0 or newer, `Ctrl+Alt+V`): the Dragonfly devices open in the window with their state, *+ New device*
  (a preset: size, pixel ratio, identity) opens one more beside the others, in its own locked group, so several
  clients run at once like several emulators (each with its own session: two signed-in users of a chat); each has its
  own app (▷ run on it), hot reload and stop (ADR-0074 for the device itself). A project's ▷ Run, ◉ Debug and ▭ Device
  ask which device to run on: the Dragonfly devices (shown or hidden), a new one, any other Flutter device (emulators,
  phones, Chrome, desktop) or the Devices workspace; a run never replaces a running device. Closing a device tab only
  hides it (its app and session go on; the Devices workspace shows it again); ✕ in the Devices workspace, the panel's
  ■ or the end of its session end it at once; a device nobody looked at for 30 minutes ends by itself, and a watchdog
  kills every Flutter or browser process the window no longer owns. Devices take the lowest free number; the debug
  sessions carry the device's name. The devices show only in mobile workspaces and the Devices tool. The first run
  builds Flutter web and takes about a minute; the next ones are incremental.
- *Dragonfly device* (0.20.0 or newer), the app inside VS Code like Android Studio's *Running Devices*:
  - It comes with the extension and exists only in VS Code: the extension registers a Flutter custom device
    `dragonfly` ("Dragonfly device") and turns on custom devices only for VS Code's Flutter processes (it adds
    `FLUTTER_CUSTOM_DEVICES=true` to VS Code's user `dart.env` and restarts the Dart extension, whose daemon reads
    the environment and the devices when it starts). It appears in the Dart extension's device picker;
    `flutter devices` in a terminal and Android Studio do not see it.
  - The panel's editor group is locked (0.23.0 or newer; VS Code's *Lock Group* padlock): nothing opens there,
    and its width still changes by dragging the border.
  - The panel's width (0.24.0 or newer): VS Code remembers the width it is left at, separately for each screen
    width (a 4K monitor and a laptop have their own). The first time on a screen it takes 20 % of its width,
    between 340 and 540 px. With the *Fit to window* zoom, the device grows up to 150 %: on a large screen the
    phone looks about its real size, and on a laptop it takes less. Switching workspace and back keeps this layout:
    the device always re-appears in its own locked group beside the code (the right, like Android Studio), never
    merged into the code's tab group (0.36.1 or newer).
  - The device emulation (size, density, user agent) lasts as long as the CDP connection with the browser: if
    that connection drops while the app runs, the panel reconnects and applies it again, and a frame that arrives
    with a size other than the device's also applies it again (0.23.2 or newer). Files, debugger pauses and the
    generated code go to another group. The padlock is removed and set again from the group's bar.
  - Run/Debug with that device chosen (or *Dragonfly: Run on Dragonfly Device*, the phone icon of a `.nuc`'s
    editor bar) runs the app on Flutter's `chrome` device with a windowless Chromium browser (headless: Chrome,
    Chromium, Brave, Edge or Vivaldi; if Flutter does not find Chrome, the extension points it to another one
    with `CHROME_EXECUTABLE` in `dart.env`). Like Android Studio's device view, the *Dragonfly device* panel shows
    that browser's screen and sends it taps, clicks, wheel and keyboard (Chrome DevTools Protocol). Breakpoints,
    steps, hot reload and hot restart work as in Chrome.
  - The panel's bar is the browsers' one: device (Responsive, iPhone SE/14 Pro/15 Pro Max, Pixel 7, Galaxy S20
    Ultra/A51, iPad Mini/Air/Pro, Galaxy Tab S7, Laptop, Desktop), width × height (editable, and by dragging the
    borders in Responsive), zoom (*Fit to window*, 50–150 %) and rotation; hot reload, hot restart, stop and open
    in the browser. The device always fits the panel's size, and each tap lands where it is seen. Phones and
    tablets have a frame. The screen renders and streams at the physical pixels the panel shows it at (its on-screen size × the monitor's
    pixel ratio), so it is never upscaled and stays sharp on a HiDPI monitor; it adapts as the panel grows. The
    resolution is set while the app runs, so after updating the extension re-run the device once to pick it up (0.36.3
    or newer).
  - The device is Chrome's device mode: size, density, user agent and platform, touch. Flutter uses iOS or
    Android behaviour (`defaultTargetPlatform`). The browser starts on an empty page and the app opens only
    once, already emulated; switching to another platform reloads it, changing only the size or rotating does not.
  - It is Flutter web: plugins with native code (camera, files) and `dart:io` do not work there.
  - Processes (0.27.1 or newer): when the session ends, when VS Code closes or if VS Code crashes, the app's
    `flutter run` and its headless browser close (they carry a mark in the startup URL and a separate watcher
    ends them when VS Code no longer exists; before, they stayed alive, hundreds of MB each). Closing the
    *Dragonfly device* panel stops the app after 5 minutes if the panel does not open again (not if it was opened
    in the browser). The language server stops 5 minutes after the last `.nuc` closes and starts with the next
    one; `dragonfly watch` ends if the process that started it dies. In Android Studio the IDE manages
    `flutter run` and the language server (the plugin only runs `dragonfly build`/`explain`, which end by themselves).
  - Flutter's `web-server` device does not work for this: its WebSocket debug service has no breakpoints (DWDS 27).

### 11.2 Android Studio / IntelliJ

With the Nuclear plugin (0.16.0 or newer) and the Flutter one, open the project folder (*File → Open*):

- The first time, the plugin adds the app (`build/app`) as a module of the project
  (`build/app/<name>_flutter_app.iml`, a copy of `flutter create`'s `.iml`) and offers *Reopen Project*. On
  reopening, the Flutter plugin configures it like any Flutter project: device picker, `main.dart`
  configuration, Run / Debug, hot reload and restart, DevTools.
- `dragonfly build` runs when the project opens, so the app that runs has the code of the `.nuc` files.
- Run and Debug (any configuration, also `main.dart`) run `dragonfly build` before launching the app (0.16.2 or
  newer): the app gets the packages, assets and native splash before Gradle compiles it. If the build fails, a
  notice shows the end of its output.
- Saving a `.nuc` (Ctrl+S) runs `dragonfly build` and *Hot Reload* of the running apps.
- When something fails (0.17.0 or newer) without errors in the `.nuc` files, as in VS Code: `dragonfly repair`
  in the background and, if it ends well, the same Run/Debug again. It triggers when the build fails (before
  launching or on save), when the app ends with an error code without the user stopping it (Stop), or when the
  Ctrl+S hot reload gives a compile error. A rejected hot reload does a *Hot Restart*. It repairs at most once
  every 5 minutes; after that it only reports.
- Debugging the `.nuc` (0.18.0 or newer), as in VS Code: a `.nuc` breakpoint (type *Nuclear line breakpoints*)
  has a mirror Dart breakpoint in the `.dart`; each pause opens the `.nuc` with the line highlighted; an error
  Flutter prints in the console is marked in red on its `.nuc` line (icon and mark in the bar) and the *Nuclear
  Error* window (on the right, only in Dragonfly projects) explains it, with the stack in Nuclear and the Dart
  error. Both options in *Settings → Tools → NuclearLang*.

- *Nuclear HTTP* tool window (0.30.0 or newer, ADR-0098; Alt+Shift+H, also under *Tools → NuclearLang*): the same
  as the VS Code view: every project of the workspace by platform, its components and endpoints from the contract,
  the contracts a client declares with *Update*, OpenAPI documents, environments in `.nuclear/http.json` and a
  request panel with the response pretty-printed and *copy as curl*.

### 11.3 Zed

The Zed extension (`nuclear-zed`, installed by `./install.sh` if Zed is installed) uses the same server
(`~/.local/bin/nuclear-lsp`, also installed by `./install.sh`): diagnostics, hover, completion, signature help,
go to definition, references, rename, outline, folding, quick fixes, colors by meaning (semantic tokens) and the
metrics code lens (on click, the detail comes out in a notice). It brings the **Chernobyl** and **Chernobyl
Soft** themes and the **Chernobyl Icons** / **Chernobyl Soft Icons** icons. Zed turns off by default the
server's semantic tokens, outline and folding and the code lenses; they are turned on in `settings.json`:

```json
{
  "code_lens": "on",
  "languages": {
    "Nuclear": { "semantic_tokens": "combined", "document_symbols": "on", "document_folding_ranges": "on" }
  }
}
```

The server's settings (the same `nuclear.*` of VS Code, without the prefix) go in
`"lsp": { "nuclear-lsp": { "settings": { "dialect": "flutter", "codemetrics": { ... } } } }`; the server's path,
in `"lsp": { "nuclear-lsp": { "binary": { "path": "..." } } }`.

In the gutter, ▷ next to `main()` runs the app (**Dragonfly: run**) and ▷ next to each `@test("…")`, `@widget(…)`
or `@states(…)` runs only that test (`dragonfly test -- --plain-name "…"`). The rest of a Dragonfly project is
handled with tasks (*task: spawn*, `alt-shift-t`), run from any `.nuc` of the project: **Dragonfly: run**
(`flutter run` in a terminal: `r` = hot reload, `R` = hot restart), **device** and **terminal device** (the
Dragonfly devices of §11, also from the ▷ of `main()`), **build**, **watch** (transpiles on each save), **test**,
**analyze**, **repair** and **explain the error in the clipboard** (`dragonfly explain`), besides **Nuclear:
generated code** and **Nuclear: check** of the open file.

Zed does not allow an extension web panels, own views nor actions on save. So it does not have: the Dragonfly
device inside the editor (`dragonfly device` opens it in its own window), the run-time error window, the bar's
Run/Debug with a build first, save → build + automatic hot reload (with **watch** + **run**, the reload is the
`r` key), the automatic repair, breakpoints in `.nuc` files and mixed debugging, nor the generated code view
beside it (the task prints it in the terminal).
